## Experiment 1 — accuracy

SDPA, SDPA (mem-efficient), FlashAttention-2, and Stream-CQSA at itr=1
and itr=2, in fp16 and bf16, against an exact float64 reference at
N=8192 over 10 seeds.

## Experiments 2 and 3 — time and memory

The same methods plus Stream-CQSA at itr=auto with the accumulator on the
host, forward and backward, N from 8K to 16M, **fp16 only**. Each cell is
wall-clock time over peak allocated device memory in GiB.

### `itr=auto` in the paper is not `itr=auto` in the package

The shipped package starts `auto` at itr=0 and lets the planner decline to
decompose, which is correct for a library: not decomposing is both the
fastest and the smallest option when the call already fits. It is useless
for a paper about decomposition, because the planner then chose itr=0 at
every N from 8K-8M, and those rows measure the undecomposed kernel.

The paper's runs therefore start `auto` at itr=1, keeping the name. A cell
marked with a **star** is one where the planner would have chosen itr=0 and
the run forced itr=1 — so the star marks exactly where the paper's `auto`
and the package's `auto` disagree, per cell rather than in a footnote.

### Method names

The 2026-08 sweeps predate the current taxonomy.

| in the raw rows | in the tables | what it is |
|:---|:---|:---|
| `cqsa_host_itrN` | CQSA itr=N acc=GPU | streamed Q/K/V, fp32 accumulator on the GPU |
| `cqsa_acccpu` | CQSA itr=auto acc=CPU | streamed Q/K/V, fp32 accumulator on the host |
| `cqsa_auto_itrN` | *not reported* | the all-on-GPU variant: deprecated, dominated by the baselines it exists to rescue |

`cqsa_auto_itrN` is easy to mistake for the acc=GPU column because of the
name. It is not: it keeps the whole input set device-resident **and** adds
an accumulator, so it runs out of memory earlier than plain SDPA.
